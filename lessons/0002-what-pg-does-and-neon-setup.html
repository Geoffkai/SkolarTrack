What pg Does — and How to Use Neon.tech

The bridge between your Express server and your PostgreSQL database, explained clearly.

1 The Problem pg Solves

Your Express server runs on Node.js. Your database runs on Neon.tech (PostgreSQL). These are two completely separate programs, potentially on different computers. How does Node.js talk to PostgreSQL?

It can't — not directly. Node.js doesn't know how to speak PostgreSQL's protocol. That's exactly what pg (node-postgres) does: it's the translator.

Your Express server
Node.js, running locally
→
pg
the translator
→
Neon.tech
PostgreSQL, in the cloud

pg handles the connection, sends your SQL over the internet, and gives you the results back as JavaScript objects.

You write normal JavaScript. You write normal SQL. pg handles everything in between — opening a network connection, sending the query, parsing the response, and returning rows as a JavaScript array you can use.

2 Pool vs Client — Which One You Use

pg gives you two ways to connect: Client and Pool.

Client = one connection, you manage it manually. You connect, use it, disconnect. If you forget to disconnect, you leak a connection. Don't use this in a web server.

Pool = a managed group of connections. You ask the pool for a connection when you need one, use it, and it goes back automatically. Multiple requests can be handled simultaneously. This is what you use.

Rule for SkolarTrack Always use Pool. Create one pool when the server starts, export it, import it in your models. Never create new connections per request.

4 The Actual Code

Step 1 — Install (run in terminal, inside server/):

npm install pg dotenv

Step 2 & 3 — Your server/.env file:

# Paste the connection string from Neon.tech dashboard here
DATABASE_URL=postgresql://username:password@ep-something.us-east-2.aws.neon.tech/neondb?sslmode=require
JWT_SECRET=some-long-random-string-here
PORT=3000
JWT_EXPIRES_IN=7d
The ?sslmode=require part is important Neon.tech requires SSL. Your connection string from Neon will already include it. Don't remove it.

Step 4 — Create server/src/db.js:

const { Pool } = require('pg');
require('dotenv').config();

const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
  ssl: { rejectUnauthorized: false }  // Required for Neon.tech
});

module.exports = pool;

That's the whole file. One pool, exported. Now any model can import it.

Step 5 — Using pool.query() in a model (example: server/src/models/userModel.js):

const pool = require('../db');

// Find a user by email
const findByEmail = async (email) => {
  const result = await pool.query(
    'SELECT * FROM users WHERE email = $1',
    [email]   // $1 gets replaced with this value — prevents SQL injection
  );
  return result.rows[0];  // rows is an array; [0] = first match
};

module.exports = { findByEmail };
What is $1? Instead of writing '...WHERE email = ' + email (dangerous — SQL injection!), you use $1 as a placeholder and pass the real value in the second argument as an array. pg safely substitutes it. Always do this for any user-supplied data.

What result looks like — when you await pool.query(), you get back an object:

{
  rows: [
    { id: 1, email: 'juan@example.com', role: 'student', name: 'Juan' }
  ],
  rowCount: 1,
  // ...other pg metadata you mostly don't need
}

Your data is always in result.rows. It's a plain JavaScript array of objects, where each object is one row and each key is a column name.

5 The /health Route That Proves It Works

Once db.js exists, wire a /health route that actually queries the database. This is your proof that the whole chain works.

server/src/app.js — simplified skeleton:

const express = require('express');
const pool    = require('./db');
require('dotenv').config();

const app = express();
app.use(express.json());

app.get('/health', async (req, res) => {
  try {
    await pool.query('SELECT 1');  // Simplest possible query — just checks connection
    res.json({ status: 'ok', db: 'connected' });
  } catch (err) {
    res.status(500).json({ status: 'error', message: err.message });
  }
});

module.exports = app;

server/index.js — entry point only:

require('dotenv').config();
const app  = require('./src/app');
const PORT = process.env.PORT || 3000;

app.listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
});

Run it with node index.js from inside server/. Then open Thunder Client and hit GET http://localhost:3000/health. You should see:

{ "status": "ok", "db": "connected" }
If you see this — Day 1 is done Your server is running. Your database is connected. You can build everything else on top of this. Commit it immediately.
